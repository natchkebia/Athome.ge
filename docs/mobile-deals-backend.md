# დღის შეთავაზება — ფრონტის ინტეგრაცია

2026-11-19. მთავარი გვერდის მობილური ბლოკი (≤560px) მორგებულია ბექენდის მოწოდებულ `isDealOfDay` + `dealOfDayEndsAt` კონტრაქტზე.

## მონაცემები

- პრიორიტეტულია `/api/storefront/home.dealsOfDay`-დან `isDealOfDay=true` პროდუქტი. სიის სახელი თავისთავად დღის შეთავაზებას არ ნიშნავს: ბექი აქ ჩვეულებრივ ფასდაკლებებსაც აბრუნებს.
- სარეზერვოდ მოწმდება `/api/storefront/products/deals`-ის დაბრუნებული პროდუქტებიც. ერთი პროდუქტი ორჯერ არ ჩანს; home-ის ჩანაწერს პრიორიტეტი აქვს.
- დღის შეთავაზებას ფასდაკლება არ მოეთხოვება. ფასებია `effectivePrice` და optional `compareAtPrice`; გადახაზული ფასი და პროცენტი მხოლოდ რეალური ფასდაკლებისას ჩანს.
- ტაიმერი იყენებს მხოლოდ `dealOfDayEndsAt`-ს — ISO 8601 აბსოლუტური დრო `+04:00` ან `Z` offset-ით. `activePromotion.endsAt` დამოუკიდებელი აქციის ვადაა და დღის ტაიმერს არ მართავს.
- დროის გარეშე ან არასწორი დროისას ჩანს `-- -- --`. გვერდის განახლება ვადას არ აგრძელებს.

## ვადა და ქეში

ბექის მოწოდებული აღწერით home-ის ქეში 3 წუთია, სიების — 60 წამი; ფრონტის SSR მოთხოვნები დამატებით 60 წამით ქეშდება.
ცნობილი ვადის ამოწურვისთანავე ფრონტი თვითონ მალავს დღის ბარათსა და მის ტაიმერს, მიუხედავად ქეშში დარჩენილი `isDealOfDay=true`-ისა.
ამ ბარათს ჩვეულებრივ შეთავაზებად აღარ გადააქცევს; სხვა აქტიური ფასდაკლებები რჩება.
მარაგში არმყოფი პროდუქტი არ ჩანს. საბოლოო ფასი და მარაგი კალათაში/შეკვეთაზე ბექის შესამოწმებელია.

თუ საერთოდ არ არის მონიშნული დღის შეთავაზება, არსებული დიზაინის fallback-ად პირველი ნამდვილი ფასდაკლება რჩება „შეთავაზება“ წარწერით და დროის გარეშე.

## შემოწმება

`npm run test:daily-deals` იყენებს მხოლოდ სინთეტურ პროდუქტებს: timezone, ფასდაკლების გარეშე შეთავაზება, home-ის პრიორიტეტი, დუბლირება, ვადის გასვლა, ძველი ქეში, მარაგი, დროის არქონა და ფასების HTML.

მოწოდებულ ბექის ჩანაწერში დეპლოი ჯერ არ იყო შესრულებული. რეალური ინტეგრაცია საბოლოოდ შესამოწმებელია ბექის დეპლოისა და ადმინში ერთი აქტიური შეთავაზების დაყენების შემდეგ; ფრონტის ტესტები ბექის დეპლოის წარმატებას არ ადასტურებს.
